# 破产业务数据库

一个面向**破产清算、破产重整、破产和解**业务的规范性文件与指导性案例数据库。为浙江共业律师事务所郑权律师办理破产案件提供权威、可追溯的规范依据与类案支撑。

> 本数据库以 `.md` 文本形态组织，供 AI 智能体（Agent）与人工检索复用；所有法规出处严格限定于专业法律数据库，不使用网络检索与新闻/自媒体来源。

---

## 一、数据来源的选择理由

数据库的内容来源经过严格筛选，核心原则是**权威性优先、时效性优先、可追溯优先**。

### 1. 中央法规：北大法宝（pkulaw）与华宇元典（yuandian）双源

| 来源 | 角色 | 说明 |
|------|------|------|
| **北大法宝** | 检索清单 + 出处索引 | 国内最权威、收录最全的法规检索数据库，用于确定法规清单、文号、效力位阶、制定机关等元数据，并提供可追溯的官方出处链接（`pkulaw.com`）。 |
| **华宇元典** | 全文抓取主力 | 全文**无付费墙**，可直接抓取法规完整正文落盘为 `.md`；弥补北大法宝对司法解释类全文设置付费墙的短板。 |

选择双源而非单一来源的理由：

1. **北大法宝的权威性不可替代**——其法规分类、效力位阶标注、修订沿革等信息最为权威，是确定「哪些文件应当收录」的基准；
2. **北大法宝司法解释设付费墙**——仅靠北大法宝无法低成本获取司法解释全文；
3. **华宇元典全文无付费墙**——可以完整、低成本地抓取全文，二者互补，兼顾「权威性」与「可获取性」。

### 2. 地方文件：仅限浙江省

地方性法规/司法文件**严格限定收录浙江省**，理由：

- 郑律师执业地在宁波（浙江共业律师事务所），破产案件的实际管辖与适用规范以浙江省为主；
- 避免收录与本地区无关、无适用价值的外省文件，保持数据库聚焦、精炼。

### 3. 参考书籍与会议纪要：用户定向投喂

《企业破产涉税百问及经典案例解析》等专著、宁波市破产法学会及浙江省破协的培训/会议纪要，由用户定向提供，作为实务补充资料收录，不纳入网络检索范围。

### 4. 明确排除的来源

- **网络搜索引擎、新闻媒体、自媒体**——一律不作为法条依据，防止以讹传讹；
- 与破产业务无关、仅正文偶提「破产」二字的文件——按效力位阶与制定机关甄别后剔除，保证收录的是「破产主题核心文件」。

## 二、数据采集方法

数据通过**两条路线**采集，最终统一转化为 `.md` 落盘。

### 路线 A：MCP 检索采集（中央法规与浙江地方文件）

通过两个 MCP 服务器以编程方式检索并抓取法规全文：

1. **检索清单**（北大法宝 `search_article` 语义检索）
   - 以关键词矩阵检索：`破产`、`企业破产`、`破产清算`、`破产重整`、`破产和解`、`管理人`、`债权人会议`、`破产债权`、`破产财产`、`强制清算`、`公司解散清算`、`企业注销`、`金融机构破产`、`执转破`、`个人债务集中清理` 等；
   - 产出「破产法规总索引」，记录法规名称、文号、制定机关、公布/施行日期、出处链接。

2. **全文抓取**（华宇元典 `rh_fg_search` + `rh_fg_detail`）
   - `rh_fg_search` 支持按效力级别（`xljb_1`）、地域（`dy`）、时效性（`sxx`）精确过滤；
   - `rh_fg_detail` 按法规 ID 拉取全文，**无付费墙**；
   - 全文落盘为 `.md` 文件，归入对应分类目录。

3. **去重与甄别**
   - 按法规 ID 去重，避免同一文件多源重复收录；
   - 按效力位阶与制定机关甄别归属，剔除正文仅偶提「破产」二字的无关文件。

### 路线 B：用户源文件投喂（`04_用户源文件/`）

用户将 Word / Excel / PPT / PDF / CSV / HTML / TXT 等格式的原始文件放入 `04_用户源文件/`，按以下流程处理：

1. **转换**：用全局 CLI 工具 `mdconvert`（底层 `markitdown` + `pywin32` COM 接口）将源文件转为 `.md`；旧版 `.doc/.xls/.ppt` 先经 Office/WPS COM 前置转换为新版格式再转 `.md`；扫描件 PDF 需先 OCR；
2. **识别**：读取生成的 `.md`，识别其内容与性质（法律/行政法规/司法解释/部门规章/地方文件/专著/会议纪要等）；
3. **分类归档**：将 `.md` 归入对应分类目录（详见下方目录结构），无法归类的放入 `03_其他/`。

### 采集的约束与纪律

- **`04_用户源文件/` 只保留用户亲手拖入的原始文件**，不留副本、中间产物或重复残留；
- 转换产生的 `.md` 直接归档到 `01/02/03` 目标分类，不经过 `04` 中转留存；
- **`01/02/03` 三个分类目录下只保留 `.md` 文件**，源文件（PDF/Word 等）一律归入 `04_用户源文件/`。

## 三、数据清洗方法

采集到的原始 `.md` 常携带转换过程引入的噪音，统一由 `scripts/clean_md.py` 做确定性清洗。

### 清洗规则

**A. 通用机械清洗**
- 去除文件 BOM 头；
- 去除每行行尾空白（trailing whitespace）；
- 压缩连续空行：3 个及以上 → 1 个；
- 删除 base64 内嵌图片行（含 `data:image`）；
- 删除 HTML 注释页码标记行（`<!-- ===== ... -->`）、物理页定位标记（`[[PHYS_PAGE:N]]`）、扫描件页脚页码（`·111·`）。

**B. 元数据统一（法规类文件）**
- 将文件头部的「`> 字段：值`」引用块或「`- **字段**：值`」列表，统一转换为 **YAML front-matter**（`--- ... ---`）；
- 识别字段白名单：`效力位阶`、`文号`、`制定机关`、`发布机关`、`发布日期`、`公布日期`、`施行日期`、`时效性`、`效力状态`、`出处`。

**C. 扫描件冗余页眉清理**
- 删除扫描件中每页重复出现的书名/页眉行（如《企业破产涉税百问及经典案例解析》的书名页眉）。

### 用法

```bash
python scripts/clean_md.py --dry-run   # 只打印改动预览，不写盘
python scripts/clean_md.py             # 正式执行，原地覆盖
```

### 元数据规范

每个 `.md` 文件由全局 CLI 工具 `mdconvert` 固定写入元数据（Front Matter + 同名 `metadata.json`）：

- **基础字段（自动）**：`title`、`source`、`source_format`、`converted_at`、`tool`；
- **法规字段（显式注入，白名单）**：`效力位阶`、`文号`、`制定机关`、`发布机关`、`公布日期`、`发布日期`、`施行日期`、`时效性`、`效力状态`、`出处`，经 `--meta-field` 或 `--meta-file` 注入。

存量文件由 `scripts/backfill_metadata.py` 统一回填到新规范（支持 `--dry-run` 预览）。

### 扫描件 OCR 重识

扫描版 PDF（如《企业破产涉税百问及经典案例解析》）经 `scripts/reocr_book.py` 辅助重识：
- `render` / `render-next`：用 PyMuPDF 按物理页渲染为 PNG；
- `save-batch`：将单批识别结果落盘为分卷文件并更新进度；
- `merge`：全部分卷完成后合并为主 `.md`；
- 进度记录在 `.workbuddy/.ocr_progress.json`，支持跨会话断点续做。

## 四、脱敏处理方法

会议纪要、培训记录中出现的**真实人名**及索引中的**账号积分余额**属敏感信息，公开（如上传 GitHub）前需脱敏，由 `scripts/mask_db.py` 统一处理。

### 脱敏原则

1. **只处理用户明确指定的内容**——会议纪要中的人名、索引账号积分，法规/书籍/其他文件一律不动；
2. **人名采用「保留姓氏、名打码」**（如 `杨忠孝` → `杨**`），兼顾可读性与可追溯性；
3. **输出映射表** `00_索引/脱敏映射表.json`，记录「原文 → 脱敏后」的对应关系，便于审计与逆回；
4. **占位符机制**：先用不可见占位符中转替换，避免「徐」与「徐峻峰/徐璐/徐伟/徐阳光」等姓氏互相包含时的误替换。

### 处理范围

| 对象 | 位置 | 处理方式 |
|------|------|----------|
| 真实人名 | `03_其他/破产业务培训与会议纪要/*.md` | 保留姓氏、名打码（`杨忠孝` → `杨**`） |
| 账号积分 | `00_索引/破产法规总索引.md` | 正则替换为 `当前余额约 [已脱敏] 分` |

### 用法

```bash
python scripts/mask_db.py   # 执行脱敏，并写出映射表
```

### 脱敏效果示例

```json
{
  "杨忠孝": "杨**",
  "俞秋玮": "俞**",
  "任一民": "任**"
}
```

> ⚠️ 映射表 `00_索引/脱敏映射表.json` 记录了「原文 → 脱敏后」的对应关系，**含真实人名**，请妥善保管、勿随仓库公开。若需将数据库公开，建议将映射表一并移出版本库或单独加密存储。

## 五、目录结构

```
破产业务数据库/
├── 00_索引/                        # 总索引、脱敏映射表等汇总文件
│   ├── 破产法规总索引.md            # 检索清单与出处索引
│   └── 脱敏映射表.json              # 人名脱敏映射（含真实人名，勿公开）
├── 01_中央法规/                     # 中央层级规范性文件（仅 .md）
│   ├── 法律/                        # 全国人大及其常委会
│   ├── 行政法规/                    # 国务院
│   ├── 司法解释/                    # 最高人民法院
│   └── 部门规章/                    # 部委规章及规范性文件
├── 02_浙江省地方文件/               # 浙江省地方文件（仅 .md）
│   ├── 地方性法规/
│   └── 地方司法文件/
├── 03_其他/                        # 无法归入上述分类的文件（仅 .md）
│   ├── 破产业务参考书籍/
│   └── 破产业务培训与会议纪要/
├── 04_用户源文件/                   # 用户投喂的原始文件（不入库，仅本地）
├── scripts/                        # 数据处理脚本
│   ├── clean_md.py                 # .md 清洗
│   ├── backfill_metadata.py        # 元数据回填
│   ├── mask_db.py                  # 脱敏处理
│   └── reocr_book.py               # 扫描件 OCR 重识辅助
└── README.md
```

## 六、脚本一览

| 脚本 | 用途 | 用法 |
|------|------|------|
| `clean_md.py` | 清洗 `.md` 文件（去 BOM/空行/图片/页码标记，元数据转 front-matter） | `python clean_md.py [--dry-run]` |
| `backfill_metadata.py` | 存量 `.md` 元数据回填到新规范 | `python backfill_metadata.py [--dry-run]` |
| `mask_db.py` | 会议纪要人名 + 索引积分脱敏 | `python mask_db.py` |
| `reocr_book.py` | 扫描件 OCR 重识辅助（渲染/分卷/合并/进度） | `python reocr_book.py <render\|render-next\|save-batch\|merge\|status>` |

全局工具：`mdconvert`（全局 CLI，将 docx/xlsx/pptx/pdf/csv/html 转为 `.md`）。

## 七、已知局限

- 华宇元典账号积分有限，每次法规详情调用消耗积分；
- 公司法、商业银行法、保险法等上位法仅收录与破产直接相关的条款，未收录整部法律全文；
- 个别浙江地方文件（如《管理人管理工作指引》）在元典中正文为附件形式，正文待补；
- 部分司法解释在北大法宝设付费墙，仅以元典全文落盘。
