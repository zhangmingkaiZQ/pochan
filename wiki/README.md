# 破产 Wiki —— 知识层

本目录是破产业务数据库的**知识层（wiki）**，采用 LLM Wiki 模式组织：AI 智能体在原始法规/文件（`01_中央法规/`、`02_浙江省地方文件/`、`03_其他/`、`04_用户源文件/` 的 `.md` 原文）之上，**增量构建并持续维护**一套结构化、相互链接的知识页。

> 核心思想：原文层是「来源真相」（source of truth），本 wiki 层是「持续复利的知识产物」（compounding artifact）。交叉引用已就位、矛盾已标注、综合已沉淀——而不是每次提问都从零重新拼装。

---

## 目录约定

```
wiki/
├── README.md          # 本文件：wiki 导航与维护规范入口
├── index.md           # 内容索引：全部知识页的目录（带一行摘要）
├── log.md             # 时间日志：ingest/query/lint 的 append-only 记录
├── 实体/              # 实体页：程序主体（债务人、管理人、债权人、法院等）
├── 概念/              # 概念页：核心法律概念（破产原因、破产财产、别除权等）
├── 流程/              # 流程页：程序阶段（申请受理、债权申报、重整、和解、清算分配）
└── 综合/              # 综合页：跨主题的综述、对比、checklist、判例集等
```

## 知识页规范（front-matter）

每个知识页头部写 YAML front-matter，字段如下：

```yaml
---
title: 页面标题
type: 实体 | 概念 | 流程 | 综合
tags: [破产原因, 受理]
updated: 2026-09-09
sources:            # 依据的原文（相对路径，指向 01/02/03 的 .md）
  - 01_中央法规/法律/中华人民共和国企业破产法.md
---
```

- `sources` 是本页内容的**依据来源**，链接必须可点击回原文，保证可追溯。
- 页内法条引用统一写 `[[法条条文]]` 或 `《文件》第 X 条`，并尽量附带 `sources` 出处。

## 三种操作（AI 维护工作流）

### 1. Ingest（收录）
用户把新源文件放入 `04_用户源文件/` 或经 MCP 抓取新法规后，AI 应：
1. 用 `mdconvert` 转 `.md` 并归入 `01/02/03` 对应分类；
2. 读取原文，提炼关键信息；
3. **更新受影响的知识页**（实体页、概念页、流程页），补充/修正交叉引用；
4. 标注新旧内容冲突处（`> ⚠️ 冲突`）；
5. 更新 `index.md`；
6. 在 `log.md` 追加一条 `## [日期] ingest | 标题` 记录。

### 2. Query（查询）
AI 先读 `index.md` 定位相关页，再钻取详情，综合作答并**注明出处**。有价值的答案（对比表、分析、发现的关联）可**回写为新知识页**，让探索成果也复利沉淀。

### 3. Lint（体检）
定期检查：页间矛盾、被新法规取代的陈旧表述、无入链的孤儿页、缺少独立页的重要概念、缺失的交叉引用、可用检索填补的数据空白。
